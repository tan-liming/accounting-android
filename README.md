# 记账

一个纯本地的 Android 记账小工具，供两个人（或更多成员）在同一台设备上记录日常流水。Android 12 及以上，无账号、无后端、无云同步，账目只存在本机。

## 功能

- **四种流水类型**：支出、收入、对外转出、内部划转。按日记录金额与用途，可补记历史日期、编辑、删除（3 秒内可撤销）。
- **周期查看**：日 / 周 / 月 / 年。点顶部时间标签可直接弹日历跳到任意一天，右侧「今天」一键回当前周期，左右箭头做微调。周一起始、自然月、自然年。
- **统计**：收入、支出、结余，按人和按分类汇总，支出 / 收入可切换的甜甜圈饼图。金额直接标在扇区上（太窄的扇区自动降级为占比，点图例可在中心查看金额）；占比按最大余数法分配，入图扇区合计恰好 100%。零 / 负净额分类会排除并标注，此时入图合计小于页面合计；对外转出、内部划转、结余不入图。
- **记一笔**：金额、用途、成员、分类、日期、对手方；支出分类与收入分类分开（内置 13 个支出 / 6 个收入，可自定义）；默认沿用上次选的成员。
- **一句话记账（可选）**：输入一句中文描述，调用 DeepSeek 自动填表，**人工确认后点保存才入库**；设置里关掉开关后整块卡片不显示，原有手填流程完全不受影响。
- **成员管理**：任意添加、改名、删除。删除会二次确认，并一并移除该成员名下流水；软删除且可撤销、可从 JSON 备份回滚。至少保留一个成员。
- **导出与备份**：CSV 导出（当前日 / 周 / 月 / 年 / 全量）；JSON 完整备份与恢复（含成员、分类、全部流水与设置），走系统文件选择器，无需存储权限。恢复为覆盖式，可选「完整回滚」把已删流水和已停用成员一起找回。
- **外观**：固定橙色主题，白天 / 深色随系统切换（未启用动态取色）。

## 数据口径

区分这四种类型的标准是**钱有没有跨过「我们」这个主体边界**：

| 类型 | 含义 | 支出 / 收入合计 | 结余 |
| --- | --- | --- | --- |
| 支出 `EXPENSE` | 消费 | 计入支出 | 减 |
| 收入 `INCOME` | 工资、别人给我们的转账等外部流入 | 计入收入 | 加 |
| 对外转出 `TRANSFER_OUT` | 我们给别人 | **单列，不进支出合计** | 减 |
| 内部划转 `TRANSFER` | 我 ↔ 对象、账户互转 | 都不进，仅留痕 | 不参与 |

**结余 = 收入 − 支出 − 对外转出**，是主体的净现金流（流量差），**不是账户余额**，不引入账户 / 资产模型。不做共同支出分摊、AA 结算或「谁欠谁」；「按成员」指记账人 / 付款人，不是最终承担人。退款 / 报销记负数支出（红冲），不记成收入。

金额用 `Long` 整数分存储，日期用 `LocalDate.toEpochDay()`（不带时区，改设备时区也不会串天），删除用 `deletedAt` 软删除，`active_records` 视图统一过滤，所有统计与导出都走它。

## 技术实现

| 项 | 版本 / 方案 |
| --- | --- |
| 语言与 UI | Kotlin 2.0.21 + Jetpack Compose（Compose BOM 2024.09.03） |
| 构建 | Gradle 8.13、AGP 8.9.1、KSP 2.0.21-1.0.25、JDK 17+ 编译 |
| 平台 | `minSdk 31`、`compileSdk / targetSdk 35` |
| 存储 | Room 2.6.1（SQLite）存流水；DataStore Preferences 存偏好；SAF 文件做导出 / 备份 |
| 数据库 | `members` / `categories` / `records` 三表 + `active_records` 视图，v1→v2 有迁移，旧账不丢 |
| 网络 | 仅「一句话记账」用 `HttpURLConnection` 调 DeepSeek，无第三方网络库 |
| 依赖注入 | 无，`AppContainer` 手工提供 Repository |

源码结构：

```
app/src/main/java/com/duo/ledger/
├── ai/        DeepSeek 客户端、返回校验、接口地址拼接
├── data/      Repository、周期计算、偏好、备份编解码
│   └── local/ Room 实体、DAO、迁移
├── ui/        三个页面、图表、对话框、主题
└── util/      金额 / CSV 工具
app/src/test/  纯 JVM 单元测试（35 个）
```

## 构建

前置：JDK 17 或更高、Android SDK（platform 35、build-tools）。Gradle wrapper 已内置，无需本机装 Gradle。

```bash
git clone <你的仓库地址>
cd accounting
./gradlew assembleDebug
./gradlew testDebugUnitTest
```

产物：`app/build/outputs/apk/debug/app-debug.apk`。

也可以用 Android Studio 直接打开工程目录，首次打开会自动生成 `local.properties` 写入 SDK 路径。

几个注意点：

- `local.properties` 含本机 SDK 路径，已排除在版本库之外，不要手动提交。
- 工程内 `gradle.properties` **不含**本机 JDK 绝对路径。若你的 `JAVA_HOME` 指向 JDK 8，把 `org.gradle.java.home` 配到全局 `~/.gradle/gradle.properties` 指向 JDK 17+ 即可；用 Android Studio 自带 JDK 则无需配置。
- **不要改包名 `com.duo.ledger`**。改包名在系统看来是换了一个 App，旧包私有目录下的数据库会读不到，已记账目会丢。显示名称改 `res/values/strings.xml` 的 `app_name` 即可。

## 配置一句话记账（可选）

右上角「设置」里填四项：总开关、**DeepSeek API Key**、接口地址（Base URL）、模型名。默认地址 `https://api.deepseek.com`，默认模型 `deepseek-flash`；走代理 / 中转或官方改域名时，改接口地址即可，支持 `/v1` 兼容路径。

- Key 只存在应用私有目录的 DataStore，**不进代码、不进版本库、也不写进 JSON 备份**（备份是明文文件，可能流到网盘或聊天里）。
- 只在主动点「识别」时，把输入的那句话连同当前成员名单、分类名单发到你配置的地址；**不发历史流水、金额、结余**。
- 识别结果经本地严格校验（金额、类型、成员 / 分类白名单、日期）后只填表，日期识别不了就回落今天。

## 数据与隐私

- 数据库 `duo_ledger.db` 位于 `/data/data/com.duo.ledger/databases/`，其他 App 读不到，卸载会随应用一起删除。
- Android 12+ 的备份规则已显式排除数据库，账目不会进系统云备份 / 设备迁移。
- 纯本地方案唯一的真风险是卸载或清除应用数据，**建议定期导出一份 JSON 完整备份**。

## 说明

- 自用工具，未上架应用商店，不做云同步、账号、账户余额、分摊结算、提醒、小组件、小票照片、多币种。
- 已完成编译期验证与 35 个纯 JVM 单元测试；UI 交互、真机安装和旧库覆盖升级尚未做实机实测。
